# `pc_monitor` — PC host tool

Realtime display, recording and export for the STM32 ECG + body-temperature
monitor. It speaks the binary framing in
[`docs/PROTOCOL.md`](../docs/PROTOCOL.md) over USART1 at 230400 baud, and mirrors
[`App/protocol/protocol.h`](../App/protocol/protocol.h) byte for byte in
[`protocol.py`](protocol.py).

> **Status: written, and verified running headlessly against its own synthetic
> device. Never connected to a real board.** No hardware has ever fed this
> application a byte. See [Verification](#verification) below.

## Install and run

```
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

.venv/Scripts/python -m pc_monitor --demo            # no board needed
.venv/Scripts/python -m pc_monitor --port COM7       # a real device
.venv/Scripts/python -m pytest tests -q              # 251 cases
```

`--demo` synthesises 1 kHz ECG so every path — framing, plot, cards, recording,
CSV/XLSX, RTC set — is exercisable with no hardware. It cannot be mistaken for a
measurement:

* the window carries a `DEMO / SYNTHETIC` banner;
* `RecordingSession.origin` is fixed at construction from the flag, not inferred
  from the bytes, and is written into **every exported row**;
* `export.default_stem()` puts `demo` in the file name;
* `caveats()` prepends `SYNTHETIC DATA: … must not be presented as one`.

`--demo-uncalibrated` reproduces what the shipping firmware actually reports:
`TEMP_UNCALIBRATED`, so the temperature card shows `--.-` rather than a number.

## What each file is

| File | Role |
| --- | --- |
| `protocol.py` | The wire mirror: offsets, CRC-16, framing, typed payload decoders, `StreamTracker`. Largest file, and the one to read first. |
| `rtc.py` | Calendar arithmetic, independent of `App/rtc_service/rtc_calendar.c` on purpose. |
| `ring_buffer.py` | `IndexedRingBuffer` (the device sample axis), `EventRateMeter`. |
| `serial_worker.py` | Reader thread; owns all framing state so the GUI never touches bytes. |
| `recorder.py` | `RecordingSession` → per-sample rows, and the caveats that stop an export over-claiming. |
| `export.py` | CSV and XLSX (Summary / Data / Chart sheets, with an embedded line chart). |
| `demo_source.py` | `DemoDevice`, a synthetic peer that speaks the real protocol. |
| `app.py` | Qt window and `AcquisitionEngine`, the only bridge from protocol to pixels. |
| `widgets/` | `EcgPane` (pyqtgraph trace), `MetricStrip`, `ConnectionPanel`, `StatusStrip`. |

## Design decisions worth knowing

**The record is unfiltered.** `ECG_BATCH` carries raw 12-bit ADC codes because the
course metric is a 0.05–150 Hz recording bandwidth. The tool never re-filters what
it stores, and `ecg_pin_mv` is labelled a pin voltage, not a body-surface
potential — `ECG_FRONTEND_GAIN`/`_OFFSET_MV` are unverified.

**Gaps stay visible.** Every batch carries an absolute `first_sample_index`, so a
lost block shows up as a discontinuity in the exported axis and as
`missing_samples` in the Summary, instead of being stitched over. `sample_time_s`
is derived from the device axis, not from a host counter.

**Uncalibrated means blank.** When the device says `TEMP_UNCALIBRATED`, `temp_centi`
and `temp_c` are written as empty cells. The raw code is still recorded, because
that is what a later calibration needs.

**Filters are `label` + `labelOpts`.** Not a dict in `label`. See
[`widgets/ecg_plot.py`](widgets/ecg_plot.py) — the wrong form raises inside
pyqtgraph's constructor, and nothing else in the app would ever run.

## Verification

`tests/` holds 251 cases. Three groups matter for different reasons:

| File | What it pins down |
| --- | --- |
| `test_protocol_vectors.py` | 21 frames **generated by the firmware's own `crc16.c` and `protocol.c`** (see `tools/gen_protocol_vectors.py`), replayed here. Includes a stale-snapshot check that recompiles the C and diffs the JSON. |
| `test_framing.py` | CRC properties, resynchronisation, and that every `status_flags_t` bit round-trips — including the high byte `ECGP_TAIL` used to drop. |
| `test_gui_smoke.py` | Builds the real window under `QT_QPA_PLATFORM=offscreen`, clicks *Start acquisition* and *Record*, and asserts samples, plotted points and exported rows appear. |

Run the GUI group explicitly when you change anything under `app.py` or
`widgets/`:

```
QT_QPA_PLATFORM=offscreen .venv/Scripts/python -m pytest tests/test_gui_smoke.py -q
```

Building these tests found and fixed four defects that no amount of importing or
type-checking had surfaced: `QtGui.ColorRole` does not exist in PySide6 6.11,
`pg.InfiniteLine` rejects a dict `label`, `DEFAULT_WINDOW_SECONDS` was imported
but never defined, and `closeEvent()` left a session permanently recording. The
first three meant **the application could not start at all**.

## What is still unproven

* No real serial port, USB-serial quirk, or driver has ever been involved.
* No real device timing: pyqtgraph smoothness at 25 FPS on a loaded laptop.
* `--port` against hardware, including whether the firmware keeps 1 kHz while the
  UI and UART are both busy.
* The XLSX chart has been read back programmatically, never opened in Excel.

## Safety

Educational course project, **not a medical device**. Nothing here may be used for
diagnosis. Do not connect a person to this link without having thought about
isolation — see [the project README](../README.md#safety).
